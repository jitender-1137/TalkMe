# Smart Replies — Groq (hosted) Setup

Smart-reply suggestions are generated by an **OpenAI-compatible chat API**.
The default provider is **Groq** — free, very fast, and it hosts open-source
models (Llama-3.3-70B, etc.), so it gives high-quality multilingual/**Hinglish**
suggestions with **no model to run on your server**.

> **⚠️ Privacy:** unlike the old self-hosted option, the recent conversation is
> sent to Groq (a third party). It leaves your network. Review Groq's data
> policy and make sure the app's Privacy/Terms reflect this before production.

---

## How it fits together

```
Browser ──► NeoChatHub backend ──HTTPS──► Groq  (POST /openai/v1/chat/completions)
            GET /api/v1/chats/{id}/smart-replies
```

- The backend reads the recent conversation and asks Groq for a few short,
  same-language replies to the last message.
- If the provider is disabled / rate-limited / errors, the client silently
  falls back to the built-in **local rule-based chips**. Nothing breaks.
- **OFF until `AI_API_KEY` is set** (and `AI_SUGGESTIONS_ENABLED=true`).

---

## 1. Get a free Groq API key

1. Sign up at **https://console.groq.com** (free, no credit card).
2. Create an API key (`gsk_...`).
3. Keep it secret — set it via env, **never commit it**.

Free tier (verify current limits on their site): roughly ~30 req/min,
~14,400 req/day, per-model token caps. Plenty for a small/medium app.

---

## 2. Configure the backend

Config lives in `application.yml` under `app.ai` (all overridable via env). It's a
**primary → fallback chain**: Groq is tried first; Hugging Face is used only if
Groq errors / rate-limits / times out / returns nothing.

| Env var                  | Default                                | Meaning                                   |
| ------------------------ | -------------------------------------- | ----------------------------------------- |
| `AI_SUGGESTIONS_ENABLED` | `false`                                | Master switch                             |
| `AI_TIMEOUT_MS`          | `8000`                                 | Per-provider give-up time                 |
| `AI_CONTEXT_MESSAGES`    | `10`                                   | Recent messages sent as context           |
| `AI_SUGGESTIONS_COUNT`   | `3`                                    | How many chips to ask for                 |
| **Primary (Groq)** |||
| `AI_API_KEY`             | *(empty)*                              | Groq key (`gsk_...`) — **required**       |
| `AI_BASE_URL`            | `https://api.groq.com/openai/v1`       | Primary endpoint                          |
| `AI_MODEL`               | `llama-3.1-8b-instant`                 | Primary model                             |
| **Fallback (Hugging Face)** |||
| `AI_FALLBACK_API_KEY`    | *(empty)*                              | HF token (`hf_...`) — blank = fallback off |
| `AI_FALLBACK_BASE_URL`   | `https://router.huggingface.co/v1`     | Fallback endpoint                         |
| `AI_FALLBACK_MODEL`      | `Qwen/Qwen2.5-7B-Instruct`             | Fallback model (ungated)                  |

Minimal setup (Groq only):

```bash
AI_SUGGESTIONS_ENABLED=true
AI_API_KEY=gsk_your_key_here
```

Add the Hugging Face fallback (recommended for resilience):

```bash
AI_FALLBACK_API_KEY=hf_your_token_here      # from huggingface.co/settings/tokens
```

### Model choices
- Primary (Groq): `llama-3.1-8b-instant` (default; 14,400 req/day + 500K tokens/day
  free, fast), `llama-3.3-70b-versatile` (best quality, but only ~1K req / 100K
  tokens per day free), `qwen-2.5-32b`, `gemma2-9b-it`.
- Fallback (HF): any router model. Prefer **ungated** ids like
  `Qwen/Qwen2.5-7B-Instruct` — `meta-llama/*` is gated (needs license approval → 403).
  The HF token must be **fine-grained with "Make calls to Inference Providers"** enabled. HF free
  credit is tiny (~$0.10/mo) then pay-as-you-go — it's a safety net, not a workhorse.

### How the fallback behaves
- Groq returns suggestions → used; HF is **not** called.
- Groq fails/empty **and** `AI_FALLBACK_API_KEY` is set → HF is tried.
- Both fail → endpoint returns `[]` and the client shows local rule-based chips.
- Logs: `smart-reply: primary produced nothing … trying fallback provider`, then
  `returning N suggestion(s)`.

## 3. Verify

```bash
# 1. The key + model work (raw Groq call):
curl https://api.groq.com/openai/v1/chat/completions \
  -H "Authorization: Bearer $AI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "llama-3.3-70b-versatile",
    "response_format": {"type":"json_object"},
    "messages": [
      {"role":"system","content":"Reply ONLY with JSON {\"replies\":[...]} — 3 short chat replies. Mirror the user'\''s Hinglish (Latin letters, never Devanagari, never English)."},
      {"role":"user","content":"Them: kya kr rahe ho"}
    ]
  }'

# 2. Backend endpoint (needs a valid auth token + chat id):
curl -s https://<your-app>/api/v1/chats/<chatId>/smart-replies \
  -H "Authorization: Bearer <token>" | jq

# 3. In the app: open a chat, have the OTHER side send a message → chips appear.
#    Backend log shows "smart-reply: provider returned N suggestion(s)".
```

Empty suggestions? Check: `AI_SUGGESTIONS_ENABLED=true`, `AI_API_KEY` set and
valid, model id correct, and the last message in the chat is **incoming** (no
suggestions on your own last message). Watch backend logs for
`smart-reply: provider returned HTTP 401/429 …` (bad key / rate limit).

## Switching providers (OpenAI-compatible)

The backend just calls `{base-url}/chat/completions`, so any OpenAI-compatible
provider works by changing three values:

| Provider   | `AI_BASE_URL`                                   | Notes                          |
| ---------- | ----------------------------------------------- | ------------------------------ |
| Groq       | `https://api.groq.com/openai/v1`                | default                        |
| OpenRouter | `https://openrouter.ai/api/v1`                  | use a `:free` model id         |
| Cloudflare | `https://api.cloudflare.com/client/v4/accounts/<id>/ai/v1` | Workers AI            |
| Ollama     | `http://localhost:11434/v1`                     | local, no key                  |

## Deploying the change

Because the UI is bundled into the backend jar, a backend-only restart does NOT
refresh the browser bundle. Rebuild the jar (auto-rebuilds + bundles the
frontend) and redeploy:

```bash
cd TalkMe
./gradlew clean bootJar     # rebuilds frontend export + bundles it
java -jar build/libs/<your-app>.jar
```
